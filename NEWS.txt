0.5
===

Upgrading
---------
    - Spark 4.0 / Scala 2.13 / JDK 17 is now the default build (CASSANALYTICS-34) and JDK 17 is required for
      default build. Spark 3 is still supported.

    - Reader and writer use SSTable version for selecting bridge version instead of the Cassandra release version
      (CASSANALYTICS-24):

      * The `spark.cassandra_analytics.cassandra.version` option has been removed. It was
        previously used to pick the Kryo registrator before the cluster version was discovered;
        all bundled bridges' registrators are now registered up front. The option is silently
        ignored if still set.

      * `ClusterInfo.getLowestCassandraVersion()` (returning `String`) was replaced by
        `ClusterInfo.getBridgeVersion()` (returning `CassandraVersion`). The same rename applies to
        `IBroadcastableClusterInfo` and `BulkWriterConfig`. Custom `ClusterInfo` implementations
        must be updated.

      * To fall back to the previous behavior, set
        `spark.cassandra_analytics.bridge.disable_sstable_version_based=true`.

    - CDC persisted-state wire format changed (CASSANALYTICS-184). `CdcState.ReplicaCountSerializer`
      now writes the replica-count map size as an `int` rather than a `short`. State written by 0.4 and
      earlier cannot be read by 0.5 and vice versa.

    - `SchemaSupplier.getCdcEnabledTables()` was replaced by `SchemaSupplier.getTables()`, which must
      return all tables, CDC-enabled or not, so the bridge schema is complete enough to deserialize
      any commit log mutation (CASSANALYTICS-182). Custom `SchemaSupplier` implementations must be
      updated.

    - S3 storage transport credentials are now modeled as `StorageAuth` rather than
      `StorageCredentials` (CASSANALYTICS-155). Custom `StorageTransportExtension`
      implementations must be updated.

    - CDC Avro record names changed for UDTs and collections (CASSANALYTICS-204). Generated names
      were previously invalid Avro names or collided between distinct types. Three changes:

      * A UDT is now a record named `<keyspace>.<udt>`, defined once per schema and referenced by
        name wherever it is used, rather than a record named `record_udt` under the namespace of
        each use. Records nested in its fields are namespaced by the UDT.

      * List and set element records use the collection's own namespace. The namespace previously
        embedded the CQL type, which is not a valid Avro name; the CQL type remains available in
        the `cqlType` property.

      * A map whose key and value both contain maps namespaces the two entry records separately so
        their full names differ. Other maps are unchanged.

      Consumers that bind to these schemas (generated classes, a schema registry, anything matching
      on record full names) must be regenerated or re-registered before upgrading. Records written
      by 0.4 and earlier do not deserialize against the 0.5 schemas.

0.4
===

Upgrading
---------
    - Absolute time values (TTL expiry timestamps, deletion times) changed from `int` to `long`
      (CASSANALYTICS-122). Three areas require attention on upgrade:

      * CDC Avro schema (breaking): `deletedAt` in the TTL record of `cdc_bytes.avsc` and
        `cdc_generic_record.avsc` changed from `int` to `long`. Consumers reading `deletedAt`
        as an integer must update to `long` before upgrading or deserialization will fail.

      * `TimeProvider` API: `referenceEpochInSeconds()` now returns `long`. Custom
        implementations must update their return type.

      * Cassandra 4.0: expiry timestamps beyond Y2038 (January 19, 2038) will throw
        `IllegalArgumentException` at runtime due to Cassandra 4.0's internal `int` limit.
        Cassandra 5.0 handles these correctly via its native `long` support.


New features
------------
    - Add support for Tuples, Tuples with collections and UDTs in the Bulk writer (CASSANALYTICS-51).
    - CDC support for Cassandra 5.0 commit logs (CASSANALYTICS-60).
    - Add flag to allow bulk write to indexed tables (CASSANALYTICS-128).
    - Support per-instance sidecar port resolution in CDC client (CASSANALYTICS-130).
    - Make KafkaPublisher class generic to publish GenericRecords for different value serializers (CASSANALYTICS-154).


Bug fixes
---------
    - Fix quote identifiers option must be set to true if TTL column name has mixed case (CASSANALYTICS-120).
    - Assign data file start offset based on BTI index (CASSANALYTICS-121).
    - Fix commitlog reading not progressing in CDC due to incorrect CommitLogReader.isFullyRead (CASSANALYTICS-124).
    - Fix incorrect hash code calculation in PartitionUpdateWrapper.Digest (CASSANALYTICS-125).
    - Flush event consumer before persisting CDC state to prevent data loss on failure (CASSANALYTICS-126).
    - Fix ReadStatusTracker to distinguish clean completion from error termination in BufferingCommitLogReader (CASSANALYTICS-129).
    - Fix SidecarCdcClient thread/resource leaks by passing it as a constructor parameter (CASSANALYTICS-142).
    - Fix various leaks in CDC caching and bridge implementation (CASSANALYTICS-143).
    - Fix BufferingInputStream failing to read last unaligned chunk (CASSANALYTICS-147).
    - Fix cannot read start offset from BTI index with big partitions (CASSANALYTICS-151).
    - Fix reading BTI may require partitions and rows indexes (CASSANALYTICS-156).
